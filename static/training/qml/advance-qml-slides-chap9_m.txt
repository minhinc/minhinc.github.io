<pre class="note">Qml is a declarative language.It has two parts Qml and Javascript. Declarative part is qml and is the object initialization code with property name and value separated by colon ':'. It supports propery binding (LHS property modified when any RHS property  changes).Javascript part is written in member functions and callback functions. Variable are assigned through '=' operator and so breaking the property binding. <span style="color:#004000;">Binding</span> or <span style="color:#004000;">State</span> Qml type can be used.</pre>
 
<pre class="note">Qml part is interpreted through c++ classes ( QQuickRectangle, QQuickText ...) where as Javascript part is interpreted through JIT interpreter.</pre>

 <pre " class="slidecontent">Qml items are simple items of Graphics Views scene graph technology where all items belong to a scene and then scene can be drawn on one or more views/Widgets/Windows. <span style="color:#004000;">Window</span> or <span style="color:#004000;">ApplicationWindow</span> Quick type generates a window where <span style="color:#004000;">Item</span> (<span style="color:#004000;">QQuickItem</span>) gets finally drawn on it. When Window/ApplicationWindow is used on qml side then there is no need for <span style="color:#004000;">QQuickView</span> class on C++ side and just <span style="color:#004000;">QQmlApplicationEngine</span> works.
  </pre>
 <pre " class="code">    Scene                       QQuickWindow/QQuickView
 ------------                  ------------------------
 |          |  mapped to       |                      |
 |   Item   | ---------------&gt; |   QQuickItem         |
 |          |                  |                      |

 <pre " class="slidecontent"> 
Qml classes can be in application or can be pushed to a library to which application would link. In case of creating library,  <span style="color:#004000;">QQmlExtensionPlugin</span> needs to be subclassed overriding its <span style="color:#004000;">registerTypes</span> and <span style="color:#004000;">initializeEngine</span> methods.
 
<pre class="note">1. Subclass <span style="color:#004000;">QQmlExtensionPlugin</span>
  &gt; Use the <span style="color:#004000;">Q_PLUGIN_METADATA()</span> macro to register the plugin with the Qt meta object system.
  &gt; Override the <span style="color:#004000;">registerTypes()</span> method and call qmlRegisterType() to register the types to be exported by the plugin.
  &gt; Override initializeEngine to initialize the extension from the uri using the engine. Here an application plugin may expose some data or objects to QML as context properties on the engine's root context.
2. Write a project file for the plugin.
3.Create a qmldir file to describe the plugin.</pre>
